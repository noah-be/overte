# Optional owned atomic-settings diagnostic

This fork-only workflow is a separate diagnostic, not a change to the
nineteen gates or a timer around their DomainServer. Its helpers preserve the
frozen standalone probe (manifest d940a5217061389a623de386b1b366021a2f7cfd69785bc6f3d65c06d6cc7c31):
exact reviewed source/native/schema, fresh random admin credential, original
initial config/argv/environment and user/IPC namespace, twenty-second readiness,
ten-second strict security-only POST, explicit stored OAuth false before/after,
all mandatory guest rows/flags and newly owned endpoint identity. It starts no
Interface, assignment, world, public mutation, account or GPU workload.

It runs on changes to its own source paths on the authorized topic branch,
or by manual dispatch of an exact reviewed SHA in noah-be/overte.
The workflow checks the lowercase 40-character event/dispatch commit against actual checkout HEAD,
uses pinned actions without persisted credentials, installs the same signed host
dependencies, and runs the existing shipped-AppArmor preparation unchanged.
It never removes/overrides profiles, lifts capabilities or changes routes.

`stage.py` creates unique owned 0700 probe/lab/output directories beneath the
canonical RUNNER_TEMP and copies only the reviewed helpers/metadata. It downloads
fixed official Noble InRelease/index/package URLs with bounded reads and checks
all recorded digests/sizes. Public gpgv must verify the host's existing trusted
Ubuntu archive keyring and exact recorded fingerprint. The signed SHA256 index
record and exact package/version/architecture/Filename/Size/SHA256 stanza must
match. Only the regular strace binary member is read from that verified archive;
its checksum/size must match. No system package installation or key import is
performed by this helper. Raw receipts and all intermediate files remain private.

The source-root unit tests are wired before native startup, using the already
verified cached signed files and executable. Twenty-six CPU contracts passed on
the current Fedora host, including the actual gpgv→signed index→package→regular
binary chain, real tiny owned strace children, zero-cap user/IPC confinement,
parent-death/deadline cleanup, exact-destination projection and strict curation.
The original missing-binary test invocation was preserved as a negative log and
corrected by explicit reviewed dependency paths. No Ubuntu/DomainServer run has
been performed with this complete workflow proposal.

The fresh original lab is prepared without starting normal services. The probe
refuses occupied original ports, a reused registry/config/admin file or changed
source/native inputs. strace starts only its new owned child; there is no attach
API. Only linkat/rename*/fsync/fdatasync are observed. Raw trace/native/tracer
streams each retain at most 256 KiB via held regular FDs while continuing to
drain. The independent observer bound is thirty seconds, with two seconds plus
200 ms cleanup; neither readiness nor POST deadlines are extended. Original
parent-death/EXITKILL ownership is retained, and no existing CI lab is stopped.

`curate.py` reads only the bounded held private summary FD, refuses duplicate or
unknown keys, unknown enum values, non-integer/over-limit counts and contradictory
completed claims, then publishes only explicit fixed fields. Raw paths, PIDs,
descriptors, auth, environment, stdout/stderr and config are never copied.
Preparation failure writes an explicit bounded unavailable summary and exits
nonzero; it cannot make the workflow successful. Upload retains only that one
safe summary. Raw diagnostics stay under RUNNER_TEMP outside artifact globs.

Exact absolute settings destinations are privately matched only within the POST
wall-clock window. Relative paths, dirfds, split/resumed lines and sync-FD target
attribution remain unknown. Log draining can lag POST; the second full retained
marker check includes startup and is not claimed to be POST-only. Truncation is
explicit. A failed link can be recoverable, so matching errno plus a commit marker
is correlation only: `settingsCommitCause` always remains `not-established`.
Ptrace can affect timing and Ubuntu LSM/Yama may refuse it. No bypass is permitted.
An isolated successful probe is not repair or causality proof for the historical
hosted world-lifecycle failure. Real Ubuntu execution/actionlint/security checks
remain parent-owned acceptance steps.
