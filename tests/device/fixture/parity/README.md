# Shared web and media reference

This repository-owned diagnostic is the same input for iOS, Phone and Pico.
It is not a replacement for normal app entry points or proof of client parity.
The existing controlled six-entity fixture remains unchanged.

Start `python3 tests/device/fixture/serve.py --bind 0.0.0.0 --public-host
192.0.2.10 --ready-file /tmp/overte-web-reference.json` from the repository root,
using the lab host address reachable by the devices. The ready file's
`webParity.scriptUrl` is an ordinary client script that can be loaded through
Running Scripts. It creates one temporary local Web entity in front of the
avatar and a `WEB TEST` tablet button. Stopping the script disconnects its
handlers, removes its button and deletes only its own entity. Approve the
explicit `scriptURL` under the client's existing script-consent flow. Do not
change consent or resource policies just to make this diagnostic run.

Repeat the same actions on each exact built artifact:

1. Record source revision, artifact checksum, build configuration, device OS,
   browser provider/runtime and the reference MP4 checksum from ready metadata.
2. Observe both the world entity and tablet. Increment the DOM counter; enter
   Unicode, a number, invented password text and multiline text; scroll to
   marker 4. Switch inputs and close/back to check keyboard focus and geometry.
3. Choose a nonprivate test image through the real OS chooser, check its preview,
   cancel, and repeat after background/resume. No entered text or filename is
   sent through the echo protocol or stored by the fixture server.
4. Press Play. Hear the tone and observe the encoded square moving, changing
   colors and **video** frame numbers. Observe several cycles in both surfaces,
   seek to four seconds, pause and resume. Browser `currentTime` alone cannot
   establish that native world capture composites moving video pixels.
5. Press Send echo request. The displayed response must come through the real
   native EventBridge into the ordinary Overte script and back. Check that
   `scriptURL` reports injection on the world entity. No substitute WebChannel
   or mock EventBridge is installed by this page.
6. Navigate to the second same-origin document, then Back and Reload. Run a
   second fixture server on a different port and enter its page URL in the
   navigation field. Ordinary DOM/input/media must remain available there, but
   echo must time out. The diagnostic script deliberately does not validate the
   origin of its bounded echo: rejection must come from the native source grant.
   Return to the original origin and verify echo works again.
7. Play the looping tone, then hide/close/replace the surface, background/resume
   and stop the client script. Observe silence and no stale input/bridge work.
   The page has no cooperative pause-on-background/close handler, so that cannot
   conceal a missing native lifecycle stop. Repeat source replacement while a
   document, chooser or input operation is pending.

Record observed outcomes and logs per surface/client, including any unsupported
media or input behavior. A server ready file, HTTP request, player time or host
test is not device acceptance. The fixture neither completes issues nor changes
the acceptance registry. This page is diagnostic content; normal Create, Chat,
Snapshot, Scripts and Assets still require their own real entry-point journeys.

## Media provenance and transport

`reference.mp4` is original test data generated by `generate_video.py`. It is
six seconds of 192×108 RGB-derived H.264 Constrained Baseline, 12 fps, with a
440 Hz mono AAC track at 22050 Hz. Every encoded frame has a white counter and
moving square; the background is red, green and blue for two seconds each.
It is distributed under Apache-2.0, with no third-party artwork or recording.

Generation requires FFmpeg with libx264 and AAC encoders:

```bash
python3 tests/device/fixture/parity/generate_video.py --output /tmp/reference.mp4
```

The checked-in version was generated with FFmpeg 8.1.3. Different encoder
versions may produce different bytes; regeneration does not establish the
checked-in checksum. `reference.json` binds the distributed bytes, and fixture
startup verifies that checksum. The server supports exact single byte ranges
(`206`), suffix ranges, `HEAD`, `If-Range` and unsatisfiable ranges (`416`) for
native browser streaming/seek. No codec executable is required just to serve
or run the repository checks. Local decoding/HTTP checks qualify this input;
they cannot qualify a mobile browser's compositor or audio route.
