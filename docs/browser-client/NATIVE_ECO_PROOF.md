The pinned release is Overte 2026.04.1, commit `f91d15a08587dcd37c642234424b3215dd331724`. Primary sources establish:

- [`PerformanceScriptingInterface::setRefreshRateProfile`](https://github.com/noah-be/overte/blob/f91d15a08587dcd37c642234424b3215dd331724/interface/src/scripting/PerformanceScriptingInterface.cpp) delegates to RefreshRateManager and emits settingsChanged. It does not call setPerformancePreset, Render setters or LOD setters.
- [`PerformanceManager::setupPerformancePresetSettings`](https://github.com/noah-be/overte/blob/f91d15a08587dcd37c642234424b3215dd331724/interface/src/PerformanceManager.cpp) maps UNKNOWN to the platform-selected ordinary native preset and applies its Render/LOD defaults. Constructor CUSTOM bypasses that ordinary initialization. This experiment uses the exact normal production Interface.json payload and never writes either constructor preset/profile field.
- [`RefreshRateManager`](https://github.com/noah-be/overte/blob/f91d15a08587dcd37c642234424b3215dd331724/interface/src/RefreshRateManager.cpp) declares ECO0 targets 20/10/5/2/30/30 Hz for focus-active/focus-inactive/unfocus/minimized/startup/shutdown. Script ECO0 is valid; CUSTOM3 is not used.
- [`LODManager::getLODTargetFPS`](https://github.com/noah-be/overte/blob/f91d15a08587dcd37c642234424b3215dd331724/interface/src/LODManager.cpp) caps the configured native LOD target by refresh scheduling. ECO therefore changes the effective LOD target indirectly. Unchanged configured worldDetailQuality and automaticLODAdjust do **not** prove identical actual rendered detail or equal workload. Effective target and dynamic LOD angle are recorded separately.
