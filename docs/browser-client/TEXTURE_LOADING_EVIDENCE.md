# Saved Hub texture-loading evidence

This is an offline review of the exact saved Chromium/Firefox render-dispatch reports. The curated JSON retains input hashes and fixed numeric fields; current source hashes are explicitly review snapshots, not retroactive attestation of old runs. No assets were fetched. No runtime experiment was activated.

Each initial world retained 63 decoded images from 71 distinct keys, including eight failures, with 44–45 cache hits and zero decoded-image evictions. Cross-session response totals show 577/616 repeated requests, but each individual join has only six or seven repeats. Those large merged totals cannot justify a new cross-session/global cache. The request category `image` includes original and compressed payloads and error bodies. Content-Length totals are recorded response-header bytes, not upstream wire transfer or decoded memory.

The sampled full-ready boundary is only an interval: Chromium 14.067–17.108 seconds after connect, Firefox 14.262–17.300 seconds. The imageLoad sums (~6 seconds), decode sums (~2 seconds), and compressedColor sums (~20 seconds) overlap. `compressedColor` surrounds cache admission, shared pending-reader wait, the bounded two-job fetch queue, response download, KTX inspection and source creation; cached calls are included. It is not CPU decompression: the existing native KTX path already sends compressed mip levels directly to WebGL. No exact HTTP concurrency or loading critical path can be reconstructed from these finished-request aggregates alone.

Large ordinary texSubImage2D calls were observed with 2048/4096 image dimensions, reaching 207.5ms in Chromium and 267ms in Firefox. The GL wrapper's counts also include dynamic textures and driver waits for prior work, so these spans are not pure GPU time, image counts or a causal loading attribution. All four preparation experiments were disabled in the reviewed reports.

The existing opt-in bitmap path converts already decoded images without a new fetch. Its current implementation refuses premultiplied variants and retains ordinary HTML uploads; native sampler/color/orientation/source stamps and all-reader material ownership are checked before publication. The saved final browser-project GPU result has twelve literal zero-error checks per engine: six actual non-premultiplied conversions and six original premultiplied fallbacks. All owned bitmap bytes/leases/active slots and renderer geometry/texture counts reached zero. The earlier literal conversion failure is preserved. The saved attachment does not identify exact stock executable versions and is not a whole-Hub pixel oracle.

Prior stock Hub bitmap runs already exist. They prepared 33 source bitmaps and 50–51 sampler bindings, retaining 133,648,948 live bytes close to the original 128MiB bound; 33 cache evictions reflect leases still needed by rendered samplers. Increasing cache/concurrency bounds is not justified. Those older runs cannot establish a loading gain for the current source.

The proposed next qualification uses the existing original Hub harness with an explicit baseline/bitmap label, otherwise identical sources, stock browser version, viewport/density and drawing buffers, reconnect enabled and all four original fluid/movement/native gates. It adds no renderer, GPU, native or image sampling; only already retained final samples are projected after the physical journey. Unsupported/capacity variants retain the original texture path. Both unsuccessful Firefox fluid outcomes remain failures. A measured same-source gain and whole-Hub fidelity remain pending.

A separate possible optimization is preparing independent FST material-map templates concurrently with ordered application. Current source waits each definition/template sequentially, while maps inside one material already run concurrently. Current reports do not record template fanout or its critical-path wait, so no such runtime change is proposed here without a bounded measurement and ownership/ordered-overlap tests.

Failures remain honest: the bounded response collector identifies five original-image gateway failures per join (PNG upstream network, three TGA upstream HTTP, JPG origin refusal); image-cache failures total eight. The other three are unclassified by this collector. Extensions are not verified byte formats. Do not widen configured origins, invent replacement assets or attribute the remaining failures to a particular decoder.

Validation: six pure projection contracts passed in 87ms. These prove privacy, per-admission duplicate accounting, coarse readiness intervals, unknown numeric handling and observation limitations; they are not browser performance evidence.
