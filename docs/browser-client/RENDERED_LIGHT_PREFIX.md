# Rejected rendered local-light prefix experiment

The proposal preserved the original strongest-eight assignment and hid only
finite exactly-zero trailing renderer slots. Fourteen CPU contracts passed.
Actual stock Chromium154 and Firefox156 qualification **failed** the original
zero-byte full-image oracle. The production renderer is restored exactly;
its experiment and acceptance fixture are withdrawn together, with their
complete reviewed source preserved in the private frozen rejection packet.
No visitor can enable this candidate in the current browser build.

The five phases used real mapped opaque/mask/blend PBR publishers, actual
current light assignments, movement, a new HDR spotlight and source deletion.
Chromium changed2/0/2/0/0 RGB bytes; Firefox changed2/3/6/0/0, each by one level.
A source-coherent localization repeat reproduces those counts and records
bounded coordinates and RGBA pairs. All native ownership, shader-readiness,
nonblank, drawing-buffer, dynamic-image and250ms graphics-submit checks remain.
Both Worlds and the exact owned development server are cleaned up.

Separate baseline/baseline controls produce zero image differences in all five
phases in both engines. They deliberately use two full-count configurations;
their candidate-capacity assertions fail, so they are controls rather than
acceptance passes. These results do not support attributing the positive
failure to generic context noise. No image tolerance is introduced.

The installed Three0.186.1 light-count program keys and unrolled direct-light
operations change shader compiler inputs when slot counts change. Algebraic
zero does not prove identical floating-point rounding. A compiler explanation
remains a hypothesis; no driver cause or same-quality Hub speed gain is claimed.
[Exact CPU record](evidence/rendered-light-prefix-cpu-20261002.json) retains the
installed primary-source digests. [Actual GPU rejection and controls](evidence/rendered-light-prefix-gpu-20261002.json)
retain source hashes, private report digests, full-image counts and bounded
synthetic pixel coordinates. The pure bounded image-comparison contracts stay
available for future renderer qualification.
