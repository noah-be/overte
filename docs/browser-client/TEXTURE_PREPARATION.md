# Bounded static material texture preparation

Standalone TMP candidate, unactivated. No production World source changes, browser/native/GPU run or loading-speed claim.

## Primary source decision

The actual installed official Three0.186.1 source and package-lock integrity are recorded in TEXTURE_PREPARATION_SOURCE.json. Published source artifact: [Three0.186.1 npm package](https://registry.npmjs.org/three/-/three-0.186.1.tgz), whose repository metadata identifies [the official Three repository](https://github.com/mrdoob/three.js). The local primary files WebGLRenderer.js and WebGLTextures.js were read directly; no network requests were used.

WebGLRenderer.initTexture explicitly documents texture preload as avoiding first-render decode/upload lag. Its public implementation uses the ordinary 2D/cube/array texture setters, then unbinds the texture. compileAsync compiles material programs and waits for readiness, but ordinarily does not upload those material images. The current World hides a root until compilation finishes; first visible render can therefore submit its required maps synchronously. This makes bounded upload preparation source-justified, while leaving its actual performance value unproven.

Three shares GPU objects by Source plus14 sampler/format/color-space fields and gates upload by Source version or a forced new key. Our decoded image sharing does not justify a source-only shortcut. Every distinct borrowed Texture still uses the public initializer: identical sampler keys may share one actual GPU upload, different sampler keys may require another. Calls, HTTP requests, image sources and actual GPU uploads are separate quantities. Skeleton DataTexture updates must continue every frame and are deliberately excluded.

## Standalone contract

new WorldTexturePreparation(renderer,{signal}).prepare(root,assertCurrent,readerSignal?) returns only after its eligible static map initialization completes. Capture actual session/revision and root-generation authority in assertCurrent; the callable is mandatory and runs before and after each initialization. Whole-world abort, individual reader cancellation, real borrowed Texture.dispose events and deadline close only owned pending continuations/reference accounting. The helper never disposes a borrowed texture/model/bitmap, sets needsUpdate, edits samplers/geometry/shaders, enables global cache, downsamples, reads new assets or changes authorization.

Only ready HTMLImageElement, ImageBitmap and CompressedTexture maps are admitted. Dynamic/canvas/video/data/depth/render-target/cube/array/external sources stay on their original renderer path. Texture identity is deduplicated within a root and material reads are deduplicated within a traversal. A serial round-robin queue calls initTexture once per real MessageChannel task; one huge model cannot place its whole map list before all later small roots. At most64 jobs,8192 borrowed Texture references,4096 maps per root and100000 traversed objects are retained, with a30second queue deadline. References/listeners/channels are released on every outcome. CPU counters distinguish initializer calls by input family, total/max synchronous submission duration and queue ownership; they do not claim distinct GPU uploads or driver GPU time.

Eleven CPU regressions and full TypeScript checking passed. Tests use actual Three objects and actual MessageChannel task boundaries, with only renderer-driver work injected. They cover immutable borrowed ownership, Source/sampler distinctions, skipped dynamic maps, round-robin calls, authority replacement, reader/World/disposed-texture cancellation, driver failure, resource limits and deadline.

## GPU scaffold and measured acceptance

The prepared browser fixture has six cases per engine (shared/different sampler, opaque/mask/blend). It requires actual WebGL2, awaits original compileAsync, and observes actual image-bearing texSubImage2D calls. Baseline must upload on first visible draw; prepared path must upload before that draw and add no image upload during it. Identical Source/sampler must have one GPU texture, a distinct sampler two, although both paths call initTexture twice. Entire rendered image SHA must be identical to baseline with meaningful visible texture pixels, callbacks/versions unchanged, and memory.textures zero after owned release. This is an actual public-renderer scaffold; it does NOT constitute an actual browser-world/native admission proof or executed GPU result. The fixture entry imports Three once to preserve optimized module identity for instanceof checks.

The scaffold described above was executed after integration: all 12 real WebGL2 cases passed in Chromium and Firefox (24.2 seconds). Baseline/prepared hashes are identical, initial visible draw adds no image upload after preparation, actual Source/sampler GPU reuse is correct, and owned teardown reaches zero textures. This proves the standalone initializer contract. Actual World integration, ImageBitmap/compressed foreground paths and Hub responsiveness remain separate required tests.

Before any default-off World experiment, reuse current GraphicsWarmupOwner/isCurrent reader-generation ownership, capture and recheck exact asset authority, and retain original final compileAsync/readiness plus all visibility/collision/publication guards. Select only a reviewed first-visible/foreground texture scope. Initializing every hidden/offscreen root would add texture residency/upload work that normal frustum culling may defer, and is NOT justified by current data. A hard limit/refusal must remain explicit; it cannot silently drop required maps or mark an incomplete root ready.

Extend only the diagnostic harness to separate HTMLImage/ImageBitmap/compressed static uploads from tiny dynamic DataTexture uploads, record dimensions/submitted compressed bytes and first-visible phase, and correlate source-bound CPU long tasks/graphicsSubmit with normal GPU texture counts. No extra driver synchronization/query or implementation-derived unique-upload count. After exact pixel/lifecycle proof, compare an isolated source-bound actual Hub cohort with identical domain snapshot, canvas/DPR, native coexistence and fluidity gates. Keep the option off if memory/work grows or loading/scheduling does not improve. Public initTexture cannot split one4096² upload; it only offers task boundaries between maps and may shift rather than reduce total cost.
