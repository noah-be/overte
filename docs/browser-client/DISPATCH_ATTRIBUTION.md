# Sampled renderBufferDirect entry attribution (default off)

This source-only diagnostic investigates the measured Firefox renderer draw-dispatch cost without changing shader counts, renderer arguments, visibility, geometry, materials, light selection, quality, resolution or authentication. It does not optimize or authorize batching. No browser/native/GPU/server/profile/system/Git/GitHub operation was performed for this proposal. AI assistance was substantial.

## Primary source and scope

The installed, pinned Three0.186.1 primary source is authoritative for this proposal. `WebGLRenderer.js` calls `setProgram` from the public `renderBufferDirect(camera,scene,geometry,material,object,group)` boundary. Material identity changes set `refreshMaterial`, refresh public material uniforms and invoke `WebGLUniforms.upload`; a changed actual program also refreshes camera/light state. `WebGLRenderLists.js` groups opaque draws by material identity. These facts justify measuring transitions; they do not prove equivalent material values, an optimization opportunity or a Hub gain. `WebGLTextures.js:getTextureCacheKey` lists fourteen Source-dependent sampler/upload state fields; the diagnostic observes exactly those bounded fields without reading image data or URLs. `Texture.js` creates `TextureSource` in this release, so the deprecated `Source` subclass must not be used to recognize its actual instances. Exact primary-file hashes are in the manifest.

On scheduled existing RenderCpuBreakdown frames, the actual renderBufferDirect arguments identify material, geometry and Object3D identities at public call entry. These entries are not confirmed GL draw calls: Three can return without a draw, and a BatchedMesh entry can issue several calls. The retained drawsObserved/drawsWithObservedProgram/drawsWithoutObservedProgram field names count these entries; snapshot scope and entryEvidence explicitly identify that boundary. Compare renderer.info.render.calls separately; do not equate the two counters. Bounded data-descriptor lookup refuses accessors before reading getContext, useProgram or the existing public-method boundaries. A temporary instance/context-scoped `useProgram` wrapper delegates the original function with the same this/arguments/return and records only its actual program-handle identities. It neither asks the driver for a program nor assumes program-cache equivalence. If a program was already bound before the sampled interval, its identity is unknown until an actual observed useProgram call. The explicit known/unknown draw counters preserve that distinction. A first binding is not counted as a transition; null clearing calls remain calls without becoming a program identity. Fixed geometry flags record skin/instance/batch/morph/vertex-alpha variants, not the actual full compiled shader key.

Public material map fields are inspected at each observed draw. Distinct TextureSource identities and private bounded sampler tuples are counted; equal images with different Source identities stay distinct. These counts do not establish content equality, GPU residency, compatible UV transforms, immutable materials or instancing admission. Owners mean dispatched Object3D instances, not native entities. No scene traversal, borrowed mutable-material cache or persistent graph census is added.

## Bounds and ownership

The option is captured as `renderDispatchAttribution` and is false by default. It additionally requires the existing renderCpuTiming observer. The existing one-in-eight frame sampling and original timing caps remain intact. Each attribution sample permits at most4096 dispatched draws/useProgram calls,512 dispatched owners/materials/geometries,1024Sources,2048sampler tuples,128programs and256KiB charged UTF-16 sampler-key storage. It targets2ms of measured inspection time per sample; aggregate inspection budget500ms and at most512samples per World. The observed sample interval is bounded5s. Inspection timing is elapsed time around the diagnostic work, not kernel CPU accounting. A synchronous bounded operation can overrun its time target; the overrun is recorded honestly, that sample is censored, and the next inspection stops. This diagnostic cannot preempt native driver work or operating-system scheduling. Installation/restoration and wrapper-call overhead are not included in the inspection-time counter and must be considered when comparing FPS.

All operation/count/key limits stop inspection, not the original draw. Invalid input/accessors/deep descriptor chains, including color BufferAttribute.itemSize, clocks, setup, context loss, abort, renderer failure and foreign hook replacement produce fixed censored reasons. Asset-controlled getters are never called. Complete/partial aggregate sums are separate; identity sets, sampler strings and prior references are cleared on completion/failure. Returned snapshots contain fresh fixed counts only, no raw handles, Source objects, entity identifiers, names, asset URLs, pixels or exception strings. An actual isolated --expose-gc test proves finished frames release six owner/geometry/material/texture/Source/program references while the finished frame itself remains alive. This CPU proof does not claim GPU deletion.

Existing renderer, scene and camera boundaries restore exact descriptors in finally; the program wrapper does likewise and leaves a foreign replacement untouched. Original renderer/driver exceptions still propagate. A nonwritable program boundary only refuses attribution and preserves rendering and existing CPU measurement. Disabled attribution never calls renderer.getContext or touches useProgram.
