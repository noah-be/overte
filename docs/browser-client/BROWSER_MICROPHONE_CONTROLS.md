## V2 review corrections

Only the authentic Tablet `screenChanged` signal with the exact generated private Audio QML URL activates the adapter. Local `page:true` packets have no authority. A private epoch (1..2147483647, never wrapping) advances on browser navigation, authority reset and genuine native Audio departure/reentry. The generated QML echoes the epoch it received in ready/change messages; the native script never assigns a new epoch to an old message. Changes also require the Browser microphone tab. Unknown old epochs are refused, and exhaustion disables the adapter. This is a protocol ownership guarantee, not a same-page DOM identity lock or a claim about observed Qt message ordering.

Every periodic readback publishes disabled/busy controls before request delivery. One already-issued, validated same-epoch change can wait behind that readback; a successful current readback must still support the control before the change is sent. Additional intents are explicitly busy. Failure, timeout, hide, navigation and authority reset discard the queued intent. No browser operation overlaps another, and the existing eight-second deadline is unchanged. Supported gain now requires both percent and non-null actual amplitude, consistently in shared, native-helper and generated-script validation.

The v2 packet is an immutable followup against the 25-file v1 after hashes, not a replacement for historical evidence. Actual Qt/browser capture controls, microphone hardware and DSP acceptance remain pending parent-owned execution.
