# Protected affected-suite selection

The dependency policy is separate from the schema-1 suite registry. It does not
change existing fingerprints, receipts, environment profiles or reuse admission.
The policy binds every suite definition and all registry controls. Candidate
registry additions still use the existing monotonic complete route.

The trusted selector independently reads complete immutable base, candidate and
protected inventories. The exact dependency-policy blob must already exist,
unchanged and ordinary, in all three. A first deployment, graph edit, changed
selector/execution authority, unknown history, unowned delta, import-name/mode
change or nonregular input retains complete verification. Candidate policy never
supplies its own authority. There is no command-line enable, suite list or
candidate-provided exclusion map.

Already reviewed pattern/import closures are compared independently. Required
files, complete import roots, helper/data contents, discovery membership and
negative lookup inventory remain bound. An unreviewed closure stays selected
individually. Candidate-scoped suites always run. Omitted names mean unaffected
inputs; they do not mean a test passed.

The device control-plane owner now has a separate conservative component
closure: all `tests/device`, interface, libraries, scripts, domain-server,
Android, iOS, provenance and SBOM helpers, generic unittest runner, requirements and
platform declaration. Its full component digest must match the protected reader
review on both sides. This retains the actual clock/audio/process/IPC tests on
relevant changes, including changed reader implementations and historical child
variants. Native fixtures use `-I ROOT`, so the device identity also binds the
complete repository native lookup inventory, including unknown extensionless
headers and historical root headers. Only a finite reviewed list of existing
CI-owned leaves may omit bytes; every path, mode and type stays bound. Component
inputs always override that independence list. The selector refuses non-CI
exemptions. The dependency policy itself keeps path/mode/type while its exact
raw bytes are separately authenticated across all three trees, avoiding a
self-referential digest.

The fixed reviewed product owners also use this complete lookup identity:
web entity visibility, LOD preferences, goto dialog script, recorded voice native,
shared script behavior, device result schema, device Jenkins regressions,
performance contracts, SafeLanding, embedded web policy, account auth dispatch,
snapshot native, document tree, OBJ materials, CodeQL remediation, virtual
baton JavaScript, desktop input protocol and server console behavior. Their actual helpers/native/QML/data readers are inside
the mandatory components. Complete `tests/javascript` and `tests/performance`
components override CI document exceptions too. Each row binds its own complete
suite definition and required subjects; only these fixed content-scoped owner
names may reference the shared identity. No row supplies another inventory or
an exclusion list. Shared dependencies currently make these rows conservative
on product changes, while unrelated CI controller changes can omit them. Device
Jenkins regression selection does not start a live Jenkins or device job.

Complete SafeLanding, Mocha, server-console, unpublished-script and JSDoc trees
also override the finite CI byte exceptions. Four fixed CI owners use a
separate subject rule: project coverage, native registration, the Python
unittest runner regressions and authenticated producer protocol. Their exact source subjects must match protected,
base and candidate bytes/modes; the policy cannot supply replacement subjects.
This keeps a changed CI regression selected without coupling every product
owner to its bytes. The coverage/native registration fixtures retain real CMake
and child-directory membership. The generic runner retains every actual child,
clock, cancellation and empty-discovery check.

A smaller owner set cannot replace an existing route with broader preparation.
Existing Qt-free selections remain authoritative until an equally narrow setup
context for a subset is independently established. The protected producer still
declines unsupported subsets before preparation; no CI37 identity is relabeled.

Added import candidates anywhere and root-level import contents also
invalidate the protected lookup review. This initial reader digest is broad:
a changed component remains selected until its reader boundary is reviewed
again. It does not constitute a complete inferred dynamic call graph.

The current policy supports only the exact existing empty shared platform
profile. Other platform declarations keep the complete route. The execution
layer rejects incompatible impact/platform-inventory and delegation flags;
the actual absence of platform declarations is established by the immutable
profile proof in the selector.
No native, Android, package, security or platform owner is waived by this plan.

The selector retains the existing plan unless the new plan has a strictly
smaller owner set. Existing proven CI37/metadata/package decisions are preserved;
a broad unproved dependency owner cannot replace them with more tests.

Dynamic subsets use the existing trusted nonreusable execution path. The exact
empty shared platform proof permits `include_platform=false`, while
`full_host=true` keeps complete prerequisite preparation. Complete
host prerequisites are retained. Environment capture cannot expand the subset
back to all suites or produce partial reusable evidence. A started test failure
is returned once as failure; it never triggers an alternate execution. The
protected producer declines this new selection reason before runtime setup,
since no protected environment profile for arbitrary subsets is qualified.

The exact ordinary dependency policy and its hyphenated regression test are
independent iOS/Android host inputs. Neighboring names and executable/alias
modes keep application verification. Existing native, browser and package
routers already treat these host leaves independently. The policy is Python
input for the pinned CodeQL generation; the transition and unsupported forms
retain the existing conservative language gates.

Each policy row records setup ownership. `host-full` subsumes the narrower
labels in the reported union. Unproved owners retain `host-full`; the labels do
not currently alter provisioning. Future setup reduction needs a separate
review of actual executable, compiler, loader, Python/Qt/Java and fixture
requirements for each selected owner.

This implementation makes subsequent protected-graph decisions functional. Its
first deployment remains conservative. It does not complete the broader
per-suite audit: many repository closures still run, provisioning remains full,
and no source/runtime reuse capability is enabled.
