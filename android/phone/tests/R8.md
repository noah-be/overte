# Phone release shrinking

The `phoneInterface` release variant enables R8 with
`proguard-android-optimize.txt` and the module's `proguard-rules.pro`.
Debug and emulator variants retain their existing configuration.

Qt 5's Android bindings and the Phone activity retain their names and members
because Qt uses reflection and native code calls into Java. The protected account
store retains only the explicitly listed JNI entry points, including its native
error mapping. Other application Java code remains eligible for shrinking and
optimization. This change does not enable Android resource shrinking or remove
Qt RCC assets/native libraries.

Run `bash android/phone/tests/phone-release-config-test.sh` for the static guard.
It includes `phone-r8-contract-test.py`, which checks release activation, prevents
global optimizer bypasses, and guards the native storage and activity lookups.
These checks do not execute R8 or demonstrate runtime compatibility.

Before publishing a new APK, build the release with R8, inspect missing-class
diagnostics and the generated mapping/usage reports, and test cold start, optional
microphone permission, domain entry, touch controls, background/resume, deep links
and account persistence on a device. Repeat the clean reproducibility and signed
reference comparison for the changed APK. The already published 0.1.0 reference
predates this R8 change and must not be treated as evidence for it.
