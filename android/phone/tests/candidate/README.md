The public production wrapper reaches the actual consumer:

    android/phone/build.sh fdroid verify-candidate --help

Supply the exact source SHA, independent frozen expected-inputs document,
expected and minimum Android version codes, channel, candidate record/artifact
and all six original Shared evidence files. The Phone layer additionally
requires android-phone, exact expected version/channel, a positive signed-32-bit
version, distinct regular files (including hardlink rejection) and non-ambiguous
CLI options. Diagnostics are fixed text only. No candidate record, expected
inputs, receipt or signature is generated by this consumer.

Additionally supply both `--build-evidence PATH` and
`--expected-artifact-sha256 SHA256` to join the mandatory Android tiers. Freeze
that expected artifact digest independently, not from the received identity
record or build envelope. A missing member of this pair fails closed; a missing
receipt, named check, zero executed count, skip, scanner error, mismatched input
or network/cache contamination is rejected by the original Shared validator.
Phone calls the original SH009 verifier first and rechecks its record, inputs and
six inventory/evidence bindings afterwards. The optional tier envelope is also
distinct from those six files. The same flags work in both Phone-owned installed
candidate adapters; configured tier evidence is verified before device discovery.

Tier-join success is the original Shared
`MANDATORY_TIER_BYTES_BOUND_PRODUCER_VERIFICATION_PENDING`. All seven Phone tiers
and exact named checks must be present, but this does not authenticate a producer
or prove that the stated build/scanner/loader commands actually executed. No
receipt emitter, build process or package verifier is created here. Current
Phone mandatory package tiers target ARM64; no x86_64 equivalent-build evidence
or PH003 qualification is inferred from this envelope.

Omitting both tier flags retains the explicitly unqualified diagnostic status
PHONE_CANDIDATE_BYTES_BOUND_VERIFICATION_PENDING, never build qualification.
It proves byte/input
binding, not that arbitrary bytes form an APK. Existing native APK contents,
ABI/API/permission, ELF/16-KiB/SONAME, scanner and complete SBOM checks remain
mandatory, as do actual build provenance and SH-002 host tiers. The source-proof
channel does not authorize installation, signing, tag selection or publication.
Mark/package/maintainer decisions and signed upgrade evidence remain PH-007 work.

preflight/build still enforce original SH-010 input bindings and forbid legacy
binary selectors. --shared-evidence-contract may pin the released Shared contract
document; its hash is not an executed tier receipt. build remains fail-closed
until General publishes the actual SH001 Phone execution adapter; the SH002
read-only join and SH009 byte binding are not that adapter.
This lane does not run a native/Gradle/Conan build or modify General recipes.
